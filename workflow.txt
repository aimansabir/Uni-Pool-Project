PROJECT: UNI-POOL WEB APP

======================================================================
WORKFLOW 1: DRIVER RIDE PUBLICATION (SUPPLY SIDE)
======================================================================

Description: This workflow details how a verified driver posts a ride. It integrates Route Intelligence to auto-tag landmarks and a Ride Type Toggle to switch between "Scheduled" (for specific class slots) and "Instant/Flash" (for immediate departures).

1. Login & Verification:
   - The driver logs in via verified university email.
   - The system retrieves their vehicle details and gender verification status.

2. Ride Type Selection:
   - Option A (Scheduled): Driver selects a future time (e.g., "Leaving at 07:45 AM") specifically targeting a "08:30 AM Class Slot."
   - Option B (Instant/Flash): Driver toggles "Leaving Now."
     - Action: The system automatically sets the departure time to "Current Time + 10 mins" and marks the ride as "Urgent."

3. Route Mapping & Smart Intelligence:
   - Input: Driver inputs Start Point (e.g., "Maskan Gate") and Destination (e.g., "University Campus" or "Clifton").
   - Smart Landmark Detection: The system uses an Open-Ended Mapping Service (e.g., Google Maps/OpenStreetMap) to generate the route path.
   - Auto-Tagging: The app automatically detects and lists major landmarks along this path (e.g., "Route passes through: Patel Hospital, Nipa Chowrangi, Aladin Park").
   - Confirmation: The driver confirms these "Key Stops" to let passengers know exactly where they can be picked up.

4. Fare Estimation:
   - Smart Fare: The system calculates the trip distance and suggests a "Fair Share" price (e.g., 200 PKR per seat) to prevent overcharging.
   - Adjustment: The driver can lower this price but cannot exceed a capped limit.

5. Preferences & Capacity:
   - Gender Preference: Driver selects "Females Only" (if eligible) or "Mixed/Any."
   - Seats: Driver sets available capacity (e.g., 3 seats).

6. Publication & Broadcast:
   - The ride is published to the database with the route geometry and tagged landmarks.
   - Notification Logic:
     - If Scheduled: The system sends Emails/Notifications to passengers subscribed to that route.
     - If Instant: The system triggers a "Live Toast Popup" to all active users currently searching for rides on that route (e.g., "Clifton"), mimicking a "Right Now" alert.


======================================================================
WORKFLOW 2: PASSENGER SEARCH & BOOKING (DEMAND SIDE)
======================================================================

Description: This workflow details how a passenger finds a ride, utilizing Smart Search for landmarks and a Live Feed for urgent departures. It covers safety checks (Occupancy Mix), booking logic, and critical cancellation handling for both scheduled and instant rides.

1. Smart Search & Live Feed:
   - Input: Passenger enters their pickup location, drop-off, and Target Class Slot.
   - Landmark Matching: The system searches for any driver whose route passes through that location (generated in Workflow 1).
   - The "Live Feed" (Urgency Logic): The top of the search results highlights "Leaving Now" rides in a distinct color (e.g., Red/Orange) to mimic the urgency of WhatsApp groups, separate from standard scheduled rides.

2. Result Visualization (Safety & Fare):
   - Occupancy Check: The ride card displays the current car mix for safety: "Occupants: 1 Male (Driver), 2 Females (Passengers)."
   - Fare View: Passenger sees the fixed price per seat (e.g., "200 PKR").
   - Route Preview: Clicking the ride opens a map view showing the Driver's path and highlighting the specific stop/landmark for the passenger.

3. Booking Request (Instant vs. Standard):
   - Action:
     - For Scheduled Rides: Passenger selects a specific landmark and clicks "Request Seat."
     - For Instant Rides: Passenger clicks "Join Ride Instantly."
   - Notification: The Driver receives a notification. For "Instant Rides," this is a loud/distinct alert on their phone to ensure immediate attention.

4. Confirmation & State Update:
   - Acceptance: The driver accepts the request.
   - State Update: The seat count decreases, and the "Occupancy Mix" is updated for all future searchers.
   - Navigation:
     - Standard: Passenger receives confirmation.
     - Instant: Passenger receives the "Track Ride" link immediately since the car is about to move.

5. Cancellation Handling (Real-Time Logic):
   - Passenger Cancel: If the passenger clicks "Cancel Ride" before the driver starts, the seat is immediately freed up for others, and the driver is notified.
   - Driver Cancel (Standard): If the driver cancels a scheduled ride, all booked passengers receive an urgent "Ride Cancelled" alert to find alternatives.
   - Driver Cancel (Instant): If a driver cancels an "Instant Ride," the system shows a critical full-screen alert to the passenger to prevent them from waiting at the curb.
